# CR-IS-CAT-01C-P1H: P1 Authoring Hygiene (F2 Record Shape Parity for P1)

## Status

Final authoring-hygiene slice for `dea-catalog-information-system-functions`.
Completes the shape-parity work begun in `CR-IS-CAT-01C-P2H` (P2/P3) by
applying the same correction to the 4 generator-emitted P1 F2 records.

After this slice **all 15 F2 records in the catalogue share the canonical
shape** and the CI step 7 shape validator reports zero failures and zero
warnings.

## 1. The gap this slice closes

`CR-IS-CAT-01C-P2H` added `scripts/validate_f2_record_shape.py` and reported:

```
P2 F2 records checked: 6 (failures: 0)
P1 F2 records checked: 5 (warnings: 4)
```

The 4 warnings were the P1 generator-emitted F2 records:

| Record | Missing fields |
|---|---|
| `dea:information-system-function-data-management` | `decomposition_rationale`, `orchestration_responsibility`, `governance.{lifecycle_history, source_and_evidence, change_history}`, `execution_characteristics.{retry_recovery, error_handling}`, 11 `non_functional_characteristics` keys |
| `dea:information-system-function-transaction-processing` | same set |
| `dea:information-system-function-workflow-orchestration` | same set |
| `dea:information-system-function-integration-and-interoperability` | same set |

Root cause: `scripts/generate_p1_population.py` emitted **every** function
(F2 and F4 alike) through a single `generate_function_yaml()` path. That path
was written for F4 leaves, so F2 parents inherited F4-shaped fields:
`non_functional_characteristics` carried only `criticality`,
`governance` omitted `lifecycle_history` / `source_and_evidence` /
`change_history`, and the F2-specific `orchestration_responsibility` and
`decomposition_rationale` fields were never emitted at all.

The 5th P1 F2 (`identity-and-access-management`) is the CR-IS-CAT-01B
hand-authored worked example. It was already canonical and was **not**
regenerated by this slice.

## 2. Corrective change set

### 2.1 `scripts/generate_p1_population.py`

The generator now emits F4 and F2 records through **separate paths**:

1. **F4 first.** The existing `generate_function_yaml()` path runs unchanged
   for F4 leaves. This is a surgical change: the F4 emit path is untouched.
2. **F2 second.** Each F2 is composed by `build_f2_record(domain, f4_records)`
   from the freshly-emitted F4 child records on disk. The composed record is
   written with `yaml.safe_dump` and the README with `build_f2_readme()`.

This reuses the same shared helper that P2 (`generate_p2_population.py`) and
P3 (`generate_p3_population.py`) already use, so the F2 shape now has exactly
one definition across all three population tranches.

### 2.2 `scripts/_f2_record_helper.py`

Two additions, both additive:

- `build_f2_record()` gains an optional `f2_slug` parameter. The P2/P3 domain
  slug and the F2 record slug are identical for those tranches, but the P1
  domains differ (`isf:domain:information-and-data-management` hosts the
  `data-management` F2). Without the override the helper's per-domain
  input/output text lookup raises `KeyError`.
- `F2_INPUT_TEXT` and `F2_OUTPUT_TEXT` gain 5 P1 entries
  (`identity-and-access-management`, `data-management`,
  `transaction-processing`, `workflow-orchestration`,
  `integration-and-interoperability`).

### 2.3 Catalog index merge (latent defect found and fixed)

Running the P1 generator **silently truncated the catalogue index** from
15 domains / 50 functions down to 5 domains / 20 functions. The generator's
catalog-index block unconditionally overwrote `entities/v1-alpha/index.yaml`
with P1-only data, discarding the 10 P2/P3 domain entries that the P2 and P3
slices had added.

This defect was latent from CR-IS-CAT-01C-P2 onward: P2 and P3 each ran their
own generators *after* P1, so the clobber never surfaced in CI. It would have
surfaced on the first re-run of the P1 generator, which is exactly what this
hygiene slice does.

The block is now a **merge**: it reads the existing index, replaces only the
5 P1 domain entries with freshly-computed values, preserves all non-P1
entries, and appends a single `CR-IS-CAT-01C-P1H` change-history entry
(de-duplicated so repeated runs do not grow the history).

Verified: three consecutive generator runs produce a byte-identical file set
and exactly one P1H change-history entry.

### 2.4 `scripts/validate_f2_record_shape.py`

With the P1 gaps closed there is no out-of-scope set left, so the
P1-warnings / P2-blockers split is removed. **Every** F2 record is now a
blocker; the validator exits 1 on any deviation. The docstring is updated to
record that all 15 F2 records are generator-emitted and that all are blockers.

## 7. Governance basis

- **G-10 single source of truth for generated artefacts.** The F2 shape is
  defined once in `_f2_record_helper.py` and consumed by all three population
  generators. Re-running any generator is idempotent; the index-clobber defect
  fix enforces this for the catalog index specifically.
- **G-09 completeness evidenced, not assumed.** The shape validator asserts
  parity across all 15 F2 records with no carve-outs, so a future population
  tranche cannot silently reintroduce an F4-shaped F2.
- **Evidence before assertion.** The 8 relationship source-endpoint
  deviations and 1 README deviation surfaced during local verification were
  confirmed as false positives from ad-hoc check scoping (cross-catalogue
  sources live in ISC/ISS per CR-IS-CAT-01D section 4; the catalogue root
  README is out of the function-README scope). Neither is a catalogue defect.
- **Programme control: no forced completeness.** This slice does not add
  records, close deferred children, or reclassify forward references.
